# 대표 사진과 링크 썸네일 검증

관련: #28. 브랜치: `feat/item-covers`.

## 구현 범위

- 기존 비공개 JPEG·PNG·WebP 첨부에서 대표 지정·변경·해제. PDF와 미완료 첨부는 선택 불가.
- 보관함과 상세에서 대표 사진 → 수집한 링크 썸네일 → 기본 표지 순서 적용.
- 대표 파일을 삭제하면 선택도 함께 없어지고 링크 썸네일 또는 기본 표지 사용.
- 상세의 사진 전체 보기는 원본 비율을 유지하며 native modal dialog의 초점 이동·Esc·초점 복귀 사용.
- 이미지 응답은 사용자 세션·현재 접근 권한·항목 소유권을 확인하고 `private, no-store` 적용. 공개 버킷·이미지 최적화 캐시·만료되는 signed read URL을 사용하지 않음.
- 링크 썸네일은 YouTube oEmbed `thumbnail_url`, Instagram 정적 head `og:image` / `twitter:image` 중 허용한 CDN 주소만 사용. 영구 복제나 캐시는 하지 않고 요청 시 전달.
- 기존 DNS 고정 전송을 공통화. 허용 HTTPS 호스트·리디렉션별 URL/DNS 검사·사설 IP 거부·8초·최대 3회 리디렉션·512KiB·압축 거부를 유지. 이미지에는 JPEG·PNG·WebP MIME과 파일 헤더 검사 추가.
- 대표 사진 실패 시 링크 썸네일을 시도하고, 외부 이미지의 만료·오류·형식/크기 제한 초과 또는 브라우저 디코딩 실패 시 링크 썸네일을 한 번 시도한 뒤 기본 표지로 전환. 자동 재시도 루프 없음.

## 자동 검증

- `npm run typecheck`, `npm run lint`, `npm run build` 통과.
- 단위 테스트 102개 통과: 표지 선택·실패 전환, URL 허용 범위, DNS·MIME·용량 제한, 원본 URL 변경 시 이전 썸네일 무시, 인증·소유권, 리디렉션 재검사 포함.
- 연결된 개발 Supabase DB pgTAP 370개 통과, 모든 데이터 변경 롤백. 이 중 `item_covers.sql` 22개로 단일 대표 제약·다른 항목/사용자 사진·PDF·미완료 파일 거부·선택 해제·차단 계정·비로그인·삭제 정리 확인.
- 사용자 제공 `/reels/` 주소가 기존 URL 검사에서 거부되는 문제를 회귀 테스트로 재현한 뒤 `/reel/`로 정리하도록 수정했다. 단위 테스트 102개 재통과, 실제 입력 링크로 수집·저장을 확인했다.
- DB dry-run에서 `20261017145843_item_covers.sql` 하나만 확인한 뒤 개발 DB에 적용. 실제 스키마에서 타입 재생성.
- 기존 연결 Auth/Storage E2E 18개 중 첫 실행 17개 통과. 첨부 항목 삭제 1개는 삭제 중 상태에서 5초 URL 대기 제한에 걸렸고, 제품 코드/테스트 변경 없이 trace를 켠 해당 시나리오 재실행은 36.3초에 통과했다. 첫 실행을 전체 성공으로 취급하지 않으며, 삭제 대기 지연의 간헐 가능성은 남는다.

## Supabase 보안 Advisor

새 표지 함수는 `security invoker`이며 기존 첨부 RLS를 유지한다. 적용 후 Advisor에서 표지 관련 지적은 없었다.
기존 구성에 대해서는 `access_allowlist`의 정책 없는 RLS(INFO), 인증된 사용자가 호출하는
`authorize_current_user`·`has_app_access`의 security definer(WARN), 유출 비밀번호 보호 비활성화(WARN)가 표시됐다.
이번 변경은 이 인증 설정을 변경하지 않는다.

## 남은 범위 및 제한

- #1의 시도 기록과 사진 연결은 해당 데이터 모델 구현 후 진행. #28 전체 완료로 간주하지 않는다.
- Instagram 실게시물은 위 공개 Reel 1건에서 검증했다. 다른 게시물과 로그인/지역 제한 등은 검증하지 않았다. 정적 메타데이터가 없거나 허용 CDN/형식/크기를 벗어나면 기본 표지 사용.
- 이 Reel의 제목 메타데이터는 캡션을 길게 포함했다. 저장 전 제목을 직접 다듬을 수 있으며 자동 제목 요약은 구현하지 않았다. 설명은 가져왔지만 재료·조리 단계의 자동 구조화나 영상 내용 추출을 검증한 것은 아니다.
- 기존 저장물에 썸네일을 일괄 수집하지 않는다. 필요하면 수정 화면에서 링크를 다시 가져와 결과를 적용·저장한다.
- 외부 썸네일 가용성·만료는 플랫폼에 의존한다. 이미지 데이터의 영구 보관은 제공하지 않는다.
- 현재 DB의 정보 유형은 recipe만 허용한다. 다른 유형의 실제 데이터 연결은 유형 확장 시 검증한다.
- CI의 연결 DB와 Supabase Preview 자동 검증 설정은 #31의 별도 작업이다.
