# 비공개 첨부와 저장 재시도 검증

검증 일시: 2026-10-11~12 (Asia/Seoul).

대상: #8, `feat/private-attachments`, 연결된 Supabase 개발 프로젝트.
앱은 publishable key + 사용자 세션 + RLS를 사용한다. 관리자 키는 기존 테스트 계정 준비·정리에만 사용한다.

## 확인한 동작

- 320px Chromium에서 파일 선택·업로드·다운로드·삭제가 가로 넘침 없이 동작한다.
- 새 항목 저장이 서버에 반영된 뒤 응답을 유실시켜도 같은 요청 재시도는 한 항목만 남긴다.
- 실제 PNG가 Storage에 저장된 뒤 업로드 응답을 유실시키면 같은 요청으로 파일 전송 없이 완료 처리한다.
- 내려받은 PNG 바이트가 입력과 같고 한글 파일명을 유지한다.
- SVG, 5MiB 초과 파일, MIME와 다른 파일 식별자는 거부한다.
- 다른 사용자에게 첨부 메타데이터와 파일이 보이지 않고 파일 삭제도 차단된다. 공개 URL로 읽을 수 없다.
- 예약 취소와 허용 목록 회수 후 이미 발급된 서명 업로드 URL도 최종 Storage 기록을 만들지 못한다.
- 항목 삭제가 Storage 파일과 첨부 메타데이터를 함께 정리한다.
- DB에서 항목당 10개 제한, 완료 전 실제 크기·MIME 일치, 원문 없는 저장 요청 지문, 삭제한 항목의 재생성 방지를 검사한다.
- Storage 삭제 실패 시 첨부 메타데이터를 유지하고, 파일 식별자 불일치 시 완료 상태로 바꾸지 않는 단위 검사를 통과한다.

추가 마이그레이션은 dry-run 후 개발 DB에 적용했고 실제 스키마로 TypeScript 타입을 생성했다.
Supabase Security Advisors 결과는 변경 전후 동일하다. 추가한 비공개 트리거 함수는 일반 사용자에게 실행 권한을 주지 않는다.
기존 허용 목록 RLS 무정책, 인증용 두 definer 함수, 유출 비밀번호 보호 설정 안내는 이번 변경에서 수정하지 않았다.

## 한계와 후속 작업

- 실제 Google OAuth 왕복과 실제 휴대폰/Safari는 이 검사에 포함하지 않는다. #4의 남은 검증은 유지한다.
- 이미지 미리보기·대표 사진·카드 표지는 #28 범위다. 이 작업은 비공개 저장과 다운로드를 제공한다.
- 파일 형식 식별자 검사는 전체 문서 해석·악성코드 검사가 아니다.
- 읽기 URL은 60초짜리 bearer 링크다. 발급 후 접근 회수가 URL 자체를 즉시 취소하지는 않는다.
- 중단·이탈한 업로드는 미완료 예약으로 남을 수 있다. 같은 파일 재선택으로 재시도하거나 상세에서 삭제한다.
- 여러 파일 삭제는 Storage와 DB 사이의 단일 트랜잭션이 아니다. 실패 시 항목을 유지하지만 일부 파일은 이미 삭제됐을 수 있다.
- Storage 객체 기록을 보호하는 한정된 트리거는 예약·활성 계정·허용 목록만 검사한다. MIME·크기는 버킷과 첨부 완료 검사에서 확인하여 Storage의 사전 권한 검사에 의존하지 않는다.
- 업그레이드 후 실제 Storage API 회귀 테스트를 다시 실행한다. 관리자 DB SQL로 객체 메타데이터를 직접 삭제하지 않는다.
