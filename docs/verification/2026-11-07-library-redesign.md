# 보관함 Playful Minimalism 적용

2026-11-07 · #43 첫 구현 범위 · 기준 main `778ede5`

## 변경과 보존

시안 PR #44 머지 후 사용자의 “진행하자” 요청으로 공통 폰트·토큰·앱 헤더와 실제 보관함을 적용했다. 상세·등록/수정·안내/로그인의 구조 재설계는 포함하지 않는다. 해당 화면에는 공유 폰트와 컨트롤 스타일 변경이 전달된다.

- Pretendard 400/600을 `next/font/local`로 제공한다. 시안의 공식 WOFF2/OFL을 `app/fonts/`로 이동해 앱과 시안이 공유하며 중복 파일은 만들지 않았다. 나눔스퀘어라운드 비교 자산은 남겼다.
- Warm White 배경, Charcoal 본문, 주요 행동/선택에 제한한 Butter Yellow. 보호된 앱의 바깥 둥근 박스·그림자·그라데이션을 제거했다. 공개 안내 화면의 기존 구성은 유지한다.
- 검색은 중립색, 모바일은 검색/검색 버튼과 태그/즐겨찾기를 각각 한 행에 놓는다. 최근 저장순 문구와 보기 전환을 같은 도구 영역에 정렬한다. 새 정렬 기능은 없다.
- 사진·제목을 먼저, 태그·날짜를 아래에 배치한다. 사진 없는 카드는 큰 기본 표지를 숨기고 얇은 중립선을 사용한다. 작은 노트 그림은 빈 보관함에만 남긴다. 상세의 기존 표지 fallback은 보존한다.
- 태그는 실제 링크이므로 정적 시안보다 큰 44px 터치 영역을 확보했다. 기존 별 모양 즐겨찾기의 이름·선택·오류·pending 처리를 유지한다.
- API·DB·RPC·RLS·Storage 정책과 저장 형식을 변경하지 않았다. 뷰 쿠키, 검색/필터/페이지, 원문·출처와 `success | partial | failed`, 입력 보존은 기존 코드를 사용한다.

## 검증

- 타입 검사·lint·단위 테스트 105개·production build 통과.
- 기존 연결 Supabase E2E 19개 통과. 명령: `AUTH_E2E=1 npm run test:e2e -- --workers=1 --reporter=line`.
- 저장/수정/삭제·검색·태그·즐겨찾기·서버 HTML에서의 뷰 복원·Space 전환·실패 후 입력 보존·권한 거부·세션 갱신/로그아웃·첨부 재시도/취소·대표 표지/전체 보기 검증. Google 제공자 왕복은 자동화하지 않는다.
- 기존 긴 제목/1px PNG 표지 테스트를 확장해 320/390/768/1440px × 두 뷰의 가로 넘침 없음, 사진 없는 큰 기본 표지 숨김, 보관함 조작 대상 44px 이상, 제목 초점 외곽선과 실제 Pretendard 로딩·외부 폰트 요청 없음 확인.
- 실제 음식 JPEG를 쓰는 별도 일회성 브라우저 검사 1개 통과. 같은 네 항목을 8개 뷰/폭 조합에서 캡처했고 빈 결과·공개 안내/로그인 320px·reduced-motion도 확인했다. 이 검사는 임시 파일에 의존하므로 저장소의 정규 테스트에 추가하지 않았다.
- 폰트 요청을 1,500ms 지연시킨 로컬 Chromium 실행에서 `hadRecentInput=false` layout-shift 합계는 **0**이었다. `next/font/local`의 기본 preload/Arial fallback 보정과 시스템 fallback을 사용한다. 이 단일 개발 서버 측정은 모든 네트워크·OS의 CLS/LCP 보장이 아니다.
- 640px viewport에서 보호된 앱에 CSS `zoom: 2`를 적용한 검사에 가로 넘침이 없었다. 브라우저 메뉴 확대나 실기기 글자 크기 검증과 구분한다.

### 대비 계산

WCAG 상대 휘도 공식으로 실제 적용한 불투명 색 조합을 다시 계산했다. 검은색/흰색 21:1로 계산을 자체 확인했다. 눌림 상태의 버튼 경계가 2.98:1이었던 초안을 조정해 3.16:1로 보강했다.

| 조합 | 대비 |
| --- | ---: |
| 본문 / Warm White | 14.63:1 |
| 보조 글자 / Warm White | 4.52:1 |
| tint 전용 보조 글자 / Vanilla | 5.60:1 |
| 주요 버튼 글자 / 기본·hover·pressed 배경 | 9.28 / 8.15 / 7.49:1 |
| 입력 경계 / 흰 표면 | 3.75:1 |
| 주요 버튼 경계 / 기본·hover·pressed 배경 | 3.91 / 3.43 / 3.16:1 |
| 초점 / Warm White | 6.16:1 |
| 오류 글자 / 오류 배경 | 5.81:1 |

전체 화면의 접근성 통과를 주장하지 않는다. 장식 구분선과 disabled는 필수 조작 경계와 구분했다.

### 검사 중 발견한 테스트 문제

기존 E2E 도우미는 삭제한 계정을 메모리 목록에 계속 남겨, 재사용된 worker의 다음 `afterAll`에서 `User not found`가 발생했다. 성공적으로 삭제한 계정은 즉시 목록에서 제거하고, 허용 목록도 정리 후 비운다. 앱 권한 로직은 바꾸지 않았다. 초기 병렬 검사에서 Supabase CLI 호출도 지연되어 연결 DB 검사는 순차 실행했다. 중단된 실행이 남긴 이번 테스트 계정과 파일도 별도로 확인해 정리했다.

일회성 사진 검사는 초기 파일 선택이 hydration 전에 실행돼 선택 처리가 누락됐고, 이후 대상을 너무 넓게 잡은 이미지 선택자도 수정했다. 앱 상호작용 준비를 확인한 후 업로드하고 표지 이미지로 선택자를 제한해 최종 검사를 통과했다. 실패 시도를 검증 성공에 포함하지 않았다.

## 한계와 후속

- 실기기 Safari·스크린리더·브라우저 메뉴 확대·OS 글자 크기·운영 환경 성능은 미검증이다.
- 실제 Google OAuth 왕복, 모든 외부 SNS, 전체 상태 대비/접근성 검증을 새로 수행하지 않았다. 공개 YouTube 수집 회귀의 실제 결과는 `partial`이었다.
- 폰트 파일은 기존 479,300바이트에서 1,551,748바이트로 늘었다. 파일 크기·전송 속도 개선으로 보고하지 않는다. 두 정적 굵기는 비교한 가변 파일보다 작으며, 실제 사용에서 전송량이 문제가 되면 subset 구성을 별도 검토한다.
- DB 스키마/권한 변경이 없어 pgTAP는 재실행하지 않았다. GitHub Linked DB/Preview가 skipped이면 성공으로 보고하지 않는다.
- #43 전체 완료가 아니다. 상세·등록/수정·안내 화면의 구조 개선은 후속이며 #32/#24/#23/#1/#25의 새 기능은 추가하지 않았다.
