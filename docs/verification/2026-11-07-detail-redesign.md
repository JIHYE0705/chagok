# 레시피 상세 화면 적용

2026-11-07 · #43 두 번째 구현 범위 · 기준 main `c3e2d5a`

## 변경

이전 상세는 큰 기본 표지와 본문 다음에 재료·단계를 표시했다. 이번에는 제목/행동/태그와 제한된 높이의 사진 → 인분·시간·온도 → 재료·단계 → 팁·요약·본문·메모 → 출처·원문·첨부·삭제 순서다. 사용자 요청으로 기존 가이드의 PC 두 열·모바일 한 열 방향을 실제 앱에 적용했다.

- 768px부터 재료/단계를 약 1:2 두 열로, 그보다 작으면 재료 다음 단계 한 열로 놓는다. 재료명/분량은 의미상 짝인 `dt`/`dd`, 단계는 기본 번호가 있는 `ol`을 쓴다.
- 긴 재료명과 분량은 각각 줄바꿈하고 수치에는 `tabular-nums`를 적용한다. 분량/인분/시간/온도는 원래 문자열을 그대로 표시하며 계산하거나 추측하지 않는다. 누락 값과 비어 있는 재료/단계도 문구로 안내한다.
- 단계의 시간·온도는 본문 아래에 나눠 표시한다. 긴 본문은 조리 정보 뒤에서 약 70ch 폭과 충분한 행간으로 읽는다. 제목과 원문 내용은 자르지 않는다. 원문·근거의 기존 접기만 유지한다.
- 사진은 PC 220px/모바일 180px 높이에서 비율을 유지하고, 전체 보기/닫기/오류 fallback은 기존 `ItemCover`를 재사용한다. 사진이 없거나 최종 로딩 실패 시 큰 기본 표지를 숨긴다. 보관함 스타일은 바꾸지 않는다.
- 메타데이터 수집 기록이 있으면 조리 정보 위에 원문 비교 안내를 추가한다. 출처별 기존 한계 안내와 원문 근거·확인 상태도 유지한다.
- API·RPC·DB 스키마/RLS·입력/저장 형식은 변경하지 않았다. 분량 환산·요리 모드·단계 이동 등 새 기능은 추가하지 않는다.

## 실행한 검증

- 타입 검사·lint·단위 테스트 105개와 production build 통과.
- `AUTH_E2E=1 npm run test:e2e -- --workers=1 --reporter=line`: 연결 Supabase 브라우저 검사 **21개 통과**. 기존 19개와 새 상세 2개다.
- 새 상세 검사는 사진 유무 × 320/390/768/1440px의 8개 조합, 긴 제목/재료명/단계, `200 g · 150 ml · 180 ℃ · ½큰술 · 1~2인분`, 미기재와 빈 재료/단계, 조리 정보가 긴 본문보다 앞에 있는지 확인한다.
- PC 두 열의 좌표와 모바일 세로 순서, 가로 넘침 없음, 표지 최대 높이, 표지 요청 차단 후 큰 기본 표지 숨김과 재료 접근을 확인했다.
- 원문 전체·링크·확인 상태/값 충돌·상세 전체 제목을 보존한다. 사진 전체 보기의 Escape 닫기/초점 복귀를 확인했다. 기존 수정/저장·실패 후 입력 유지·첨부 업로드/재시도/삭제·보관함 두 뷰·인증/소유권 검사도 통과했다.
- 기존 수집 테스트에 조리 정보 위의 메타데이터 한계 안내가 표시되는지 추가했다. 실제 YouTube 수집 회귀 결과는 `partial`로 유지됐다.
- 실제 JPEG를 쓰는 별도 일회성 브라우저 검사 1개도 통과했다. 같은 항목으로 사진 전/후 8개 화면을 캡처하고 재료명/분량 영역이 겹치지 않음, 사진 디코딩/전체 보기, 출처 링크의 3px 초점, reduced-motion을 확인했다. 정규 테스트의 1px PNG 전달 검증과 구분한다.
- 640px viewport에서 앱에 CSS `zoom: 2`를 적용해 가로 넘침이 없었다. 브라우저 메뉴 확대·실기기 글자 크기 검증은 아니다.
- 실제 음식 사진이 있는 PC/모바일 및 사진 없는 모바일을 시각 검토했다. 긴 단계와 재료는 별도의 정규 테스트 데이터로도 확인했다.

### 색상과 접근성 범위

기존 의미 토큰을 재사용했다. 본문/Warm White 14.63:1, 보조 글자/Warm White 4.52:1, 단계 조건 전용 글자/Vanilla 5.60:1, 메타데이터 주의 글자/주의 배경 5.96:1이다. 장식 구분선은 조작 경계로 사용하지 않는다. 전체 UI의 접근성 통과를 주장하지 않는다.
