## 변경

기존 폼의 입력 방식·출처·원문·정리 결과를 ‘원문·출처’와 ‘저장할 내용’ 두 구역으로 구분했다. 보관함·상세에서 승인한 Pretendard·중립 배경·작은 반경·의미 색상 토큰을 이어 쓴다. 원문과 본문 기본 높이는 6줄이고 전체 값과 세로 크기 조절은 유지한다.

- 직접 작성·텍스트 붙여넣기·링크 가져오기 select와 기존 필드·이름·검증 조건을 유지한다. 제목은 필수, 원본 링크는 링크 방식에서 필수이며 다른 항목은 선택이라고 안내한다. 필수 상태는 실제 `required`와 설명으로도 전달한다.
- 최대 800px 편집 폭과 구분선·여백으로 위계를 잡는다. 인분·준비/조리 시간·온도는 공간이 충분하면 두 열이며 열 최소 너비는 16rem이다. 팁은 전체 폭을 쓴다. 좁은 화면이나 확대에서는 한 열로 내려간다.
- 가져오기와 후보 정리의 한계·원문 근거·미기재·확인 필요·수집 실패 안내를 유지한다. LinkCapture와 상세의 EvidencePanel 자체는 변경하지 않고 폼 내부의 스타일만 조정한다.
- 저장 전에는 상세 이동을 설명한다. 저장 중에는 기존 fieldset과 버튼 비활성화를 유지하며 상태 문구를 표시한다. 성공 시 ‘저장 완료’와 상세 이동 상태를 표시하고 기존 경로로 이동한다. 새 알림 라이브러리나 URL 파라미터를 추가하지 않는다.
- 초안 임시 보관·복원, 이탈 경고·덮어쓰기 확인, 실패 후 입력 보존, 중복 제출 방지와 API·DB·저장 형식은 유지한다. 안내·로그인 개편은 후속이다.

## 실행한 검사

- lint·타입 검사·production build 통과.
- 단위 테스트 107개 통과. 새 2개는 저장 중 두 구역의 비활성화·완료 상태·상세 이동·초안 정리와 연결 실패 후 원문/재료 편집·초안 복원을 확인한다.
- `AUTH_E2E=1 npm run test:e2e -- --workers=1 --reporter=line`: 기존 연결 DB 브라우저 검사 21개 통과. 등록·수정·검증 오류·연결 실패 후 입력 유지·새로고침 복원·이탈 취소·링크 중복/실패·원문 근거·보관함 두 뷰·상세·첨부·소유권/접근 제어를 포함한다. 테스트 계정에 합성 Google identity를 사용하므로 실제 OAuth 왕복 검증은 아니다.
- 기존 실외부 YouTube 메타데이터 검사는 `partial`이었다. 성공한 레시피 본문 추출로 취급하지 않는다.
- Playwright CLI로 등록/수정 각각 320/390/768/1440px에서 긴 한글 제목과 원문·재료/단계를 확인했다. 페이지 가로 넘침이 없고 폼 입력·선택·버튼·근거 펼치기·취소 링크는 44px 이상이었다. 입력값은 생략하거나 줄이지 않는다.
- 제목에서 Tab으로 요약에 이동하고 3px 초점이 보였다. PC 인분/시간 필드가 두 열임을 확인했으며 640px 화면에 CSS `zoom: 2`를 적용해 가로 넘침이 없었다. CSS 확대를 브라우저 메뉴 확대나 OS 글자 크기 검증으로 간주하지 않는다.
- 320px 링크 방식에서 필수 URL 속성과 안내, 가로 넘침 없음을 확인했다. reduced-motion에서는 저장 버튼의 transition이 0초였다. 모바일 수정과 PC 등록 캡처를 시각 확인했다.
- 기존 색 토큰만 재사용했다. 본문/Warm White 14.63:1, 보조 글자/Warm White 4.52:1, 입력 경계/흰색 3.75:1은 기존 디자인 시스템 계산값이다. 새 색상이나 대비 계산은 추가하지 않았다.
