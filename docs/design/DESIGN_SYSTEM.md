# Chagok 디자인 시스템

기준일: 2026-10-31. **브랜드 방향과 후속 구현의 기준**이며 제품 CSS에 적용된 상태가 아니다. 현황과 개선 제안은 [UI 분석](UI_AUDIT.md), 승인 이력은 [결정 기록](DECISIONS.md)을 참고한다.

## 브랜드

**Little Joy, Well Organized · Playful Minimalism**

차곡은 개인이 레시피를 모으고 정리·수정하며 다시 활용하는 아카이브다. 정갈함 80%, 위트 있는 귀여움 20%는 면적을 계측하는 규칙이 아니라 판단의 출발점이다. 음식 사진과 레시피 정보가 주인공이다. 작은 즐거움은 절제된 노랑 선택 표시, 즐겨찾기의 섬세한 변화, 빈 보관함의 작은 노트 그림 정도에 둔다.

어린이용 요리 앱·캐릭터 중심 앱·파스텔 박스의 반복·획일적인 SaaS 대시보드를 피한다. 기존 노트 자산은 보존하되 모든 카드와 화면에 반복하지 않는다. 본문은 읽기 편한 Sans를 쓰고 말투는 짧고 친절하게 유지한다.

## 컬러 토큰

아래 이름과 값은 차기 CSS custom property 기준이다. 이번 단계에서는 런타임에 추가하지 않는다.

| 토큰 | 값 | 역할·제약 |
| --- | --- | --- |
| `--color-bg` | `#FFFEFB` | Warm White, 전체 배경 |
| `--color-surface` | `#FFFFFF` | 입력·사진 주변 중립 표면, 꼭 필요한 경우만 |
| `--color-accent` | `#F4C84B` | Butter Yellow, 주요 행동·활성 표시 |
| `--color-accent-bg` | `#FFF8E7` | Vanilla, 선택·가벼운 강조 |
| `--color-text` | `#292824` | Charcoal, 제목·본문·노란 버튼 글자 |
| `--color-text-secondary` | `#777765` | Olive Gray, Warm White/흰색 위 보조 정보 |
| `--color-text-secondary-on-tint` | `#656553` | Vanilla 위 보조 정보 |
| `--color-divider` | `#E5E2D8` | 장식·내용 구분선, 필수 컨트롤 경계로 사용하지 않음 |
| `--color-control-border` | `#858572` | 흰색·Warm White·Vanilla 위 입력 경계 |
| `--color-focus` | `#62624F` | 키보드 초점, 노란 버튼 경계·선택 표시 |
| `--color-disabled-bg` | `#EDEBE4` | 비활성 배경 |
| `--color-disabled-text` | `#777765` | 비활성 글자, 사유는 활성 보조 문구로 설명 |
| `--color-success` / `--color-success-bg` | `#3D684B` / `#EFF5EE` | 저장 완료·확인 상태 |
| `--color-warning` / `--color-warning-bg` | `#795811` / `#FFF4D6` | 일부 수집·주의·확인 필요 |
| `--color-error` / `--color-error-bg` | `#A13C35` / `#FBEFEC` | 오류·삭제 등 위험 행동 |

색상만으로 상태를 전달하지 않는다. ‘일부만 수집’, ‘추출 실패’, ‘미기재’ 등의 문구와 필요한 아이콘·선택 표시를 함께 쓴다. `success | partial | failed`의 의미를 유지하며 메타데이터 수집 성공을 레시피 검증 성공처럼 표현하지 않는다.

### 대비 검증

WCAG 상대 휘도 공식으로 불투명 단색 조합을 계산했다. 일반 텍스트는 4.5:1 이상, 큰 텍스트는 3:1 이상, 식별에 필요한 UI 경계·상태는 인접색 대비 3:1 이상을 기준으로 한다. 차곡의 18~20px/600 섹션 제목은 일반 텍스트 기준을 적용한다. 비활성 컨트롤·장식 구분선은 해당 예외 범위를 구분한다.

| 조합 | 대비 | 사용 판단 |
| --- | ---: | --- |
| Charcoal / Warm White | 14.63:1 | 본문 가능 |
| Olive Gray / Warm White | 4.52:1 | 일반 텍스트 가능하나 여유가 작음, opacity 금지 |
| Olive Gray / White | 4.55:1 | 일반 텍스트 가능 |
| Olive Gray / Vanilla | 4.30:1 | 일반 텍스트 금지, on-tint 사용 |
| on-tint / Vanilla | 5.60:1 | 강조 배경의 보조 문구 가능 |
| Charcoal / Butter Yellow | 9.28:1 | 주요 버튼 글자 |
| Olive Gray / Butter Yellow | 2.86:1 | 글자·의미 있는 아이콘에 사용 금지 |
| Butter Yellow / Warm White | 1.58:1 | 색 채움만으로 컨트롤·선택 경계를 전달하지 않음 |
| control-border / White·Warm White·Vanilla | 3.75 / 3.72 / 3.54:1 | 입력 경계 가능 |
| control-border / Butter Yellow | 2.36:1 | 노란 버튼에는 focus 색 테두리 사용 |
| focus / Warm White·Butter Yellow | 6.16 / 3.91:1 | 초점·노란 버튼 경계 가능 |
| success / success-bg | 5.78:1 | 상태 글자·아이콘 가능 |
| warning / warning-bg | 5.96:1 | 상태 글자·아이콘 가능 |
| error / error-bg | 5.81:1 | 상태 글자·아이콘 가능 |

Hover·pressed·opacity·이미지 위 오버레이·실제 포커스 링의 인접색은 구현 시 다시 검증한다. 이 표는 화면 전체의 접근성 통과를 의미하지 않는다.

출처: [W3C 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).

## 타이포그래피

차기 기본 폰트 후보는 **Pretendard**다. 현재 나눔스퀘어라운드 400/700에서 실제 교체하려면 별도 대표 화면 검토와 승인이 필요하다. 손글씨·둥근 폰트로 본문의 귀여움을 만들지 않는다. 워드마크는 본문 폰트와 별개이며 이번에 확정하지 않는다.

| 역할 | 크기 / 굵기 | 행간 |
| --- | --- | --- |
| 페이지 제목 | 모바일 24px, PC 28px / 600 | 1.35~1.45 |
| 섹션 제목 | 18~20px / 600 | 1.5 |
| 카드 제목 | 16~18px / 600 | 1.5 |
| 본문·입력값·조리 단계 | 16px / 400 | 1.65~1.8 |
| 조밀한 목록 본문 | 15px / 400 | 1.6 |
| 보조 정보 | 13~14px / 400 | 1.5~1.6 |
| 버튼·선택 상태 | 15~16px / 600 | 1.5 |

기본 굵기는 400/600 두 개로 제한한다. 500은 대표 화면 비교에서 필요한 경우만 추가한다. 실제 face 없이 700 등으로 합성하지 않는다. rem 기반으로 구현하고 확대를 막지 않는다. 한국어는 단어 단위 개행을 기본으로 하되 긴 URL·연속 문자열에는 안전한 줄바꿈을 허용한다. 과한 음수 자간을 피한다.

목록 제목은 표시만 두 줄로 제한하고 상세·수정에서는 전체 내용을 읽고 편집할 수 있어야 한다. 재료 수량·시간에는 `tabular-nums`를 검토하되 `200 g · 150 ml · 180 ℃ · ½큰술 · 1~2인분`의 실제 글리프·정렬을 확인한다. 문자열을 강제로 수치화하거나 임의 계산하지 않는다.

실제 도입은 기존 `next/font/local` 패턴을 유지하고 공식 배포 버전·WOFF2·OFL을 동봉한다. 정적 400/600과 variable의 실제 바이트를 비교한 뒤 필요한 파일만 택한다. 외부 CDN 의존이나 새 UI 라이브러리는 추가하지 않는다. 설치된 Next.js의 `node_modules/next/dist/docs/01-app/03-api-reference/02-components/font.md`를 읽고 fallback·preload를 결정하며 느린 로딩의 CLS를 측정한다. [Pretendard 공식 배포](https://github.com/orioncactus/pretendard) 기준으로 라이선스와 파일을 확인한다.

## 레이아웃과 컴포넌트

- 간격은 4/8/12/16/24/32/48px 단계. 모바일 좌우 16px, PC 내용 최대 폭은 기존 1160px을 출발점으로 검토한다. 조리 본문은 약 60~70ch 이내로 제한한다.
- 바깥 앱 전체를 둥근 카드로 감싸는 구조는 축소한다. 중첩 박스 대신 여백·정렬·구분선으로 구역을 만든다.
- 카드 반경 10px(허용 8~12px), 버튼·입력 반경 8px. 그림자는 기본 없음, 떠 있는 메뉴·대화상자처럼 필요한 레이어만 사용한다. 사진은 기존 8:5 비율부터 검토한다.
- 주요 버튼은 노란 바탕·어두운 글자·진한 경계. 보조 행동은 중립색, 삭제는 오류색과 명확한 이름을 쓴다. 로그아웃까지 모든 버튼을 노랗게 만들지 않는다.
- 태그는 중립 배경 또는 텍스트 중심. 알약 모양은 태그 등 짧은 범주에만 제한하고 모든 버튼에 적용하지 않는다. 선택에는 `aria-pressed`와 경계·아이콘을 함께 쓴다.
- 조작 영역은 44px을 기본으로 확보한다. 포커스는 3px 외곽선과 간격으로 표현하며 잘리지 않게 한다. label을 유지하고 placeholder만으로 항목을 설명하지 않는다.
- 인터랙션은 필요한 경우 120~180ms의 색·opacity 변화 수준으로 제한한다. 바운스는 쓰지 않고 `prefers-reduced-motion`을 존중한다.

## 핵심 화면

### 목록

카드형·목록형과 선택 쿠키를 유지한다. 사진 → 제목 → 짧은 요약 → 태그·날짜 순으로 위계를 잡는다. 사진 없는 항목은 반복 캐릭터 대신 얇은 중립 표지나 텍스트 중심 구성을 검토한다. 음식 이미지를 임의 생성하거나 관련 없는 사진으로 대신하지 않는다.

검색·태그·즐겨찾기 필터는 상단에서 접근 가능하게 유지하고 큰 노란 검색 박스를 덜어낸다. 현재 최근 저장순 문구는 정렬 컨트롤이 아니다. 기존 페이지 탐색을 보존한다. #32의 무한 스크롤·좌측 플로팅 제목 목차는 계획을 보존하며 실제 구현·조회 성능·접근성은 별도 기능 작업으로 둔다.

### 상세

제목·사진·인분/시간 다음 재료와 조리 단계를 읽기 쉽게 구성한다. PC는 재료/단계 두 열, 모바일은 재료 다음 단계 한 열을 우선 제안한다. 재료명과 분량은 짝을 유지하고 긴 이름·미기재가 겹치지 않게 한다. 단계는 번호와 충분한 행간으로 구분한다. 긴 상세 제목은 모두 보이고 사진이 없어도 콘텐츠 시작이 밀리지 않게 한다.

원문·출처·메타데이터의 한계·첨부·삭제를 유지한다. 부가 근거는 접기 등을 검토하되 필요한 경고를 숨기지 않는다. 분량 조절·버전 이력·평가·단계 탐색 기능은 현재 구현 여부를 확인하고, 없는 기능을 시각 변경에 섞어 추가하거나 작동하는 것처럼 표시하지 않는다.

### 등록·수정

‘URL로 가져오기’와 ‘직접 작성’을 쉽게 구별하고 기존 ‘텍스트 붙여넣기’ 경로도 보존한다. 현재 select를 더 명료하게 배치하는 것부터 검토하며 새 탭이나 별도 라우트를 전제로 하지 않는다. 원문/가져온 내용과 저장할 결과는 여백·제목으로 구분하고 각 입력을 카드로 쪼개지 않는다.

제목은 필수, URL은 링크 방식에서 필수, 나머지는 선택임을 명시한다. 모든 저장 검증 규칙은 기존 코드가 기준이다. 저장 중·완료·오류를 문구로 전달하고 `role=status/alert`, pending 중 중복 제출 방지, 임시 입력 복원·이탈 경고·덮어쓰기 확인을 유지한다. 저장 완료 후 상세 이동에서 결과를 어떻게 알릴지는 구현 전에 정한다.

## 구현 승인 후 검증 기준

- 보관함 두 뷰·상세·등록/수정·로그인에 같은 토큰과 정보 위계 적용.
- 320/390/768/1440px, 긴 한글 제목·긴 단계·수치/단위·사진 유무·데이터 다수·빈 결과 확인.
- 텍스트/컨트롤/선택/포커스 대비, 키보드 순서·포커스, 확대·reflow, 터치 영역, reduced-motion 확인.
- 실제 음식 사진의 시각 검토와 private 표지 동작 검사를 구분. 테스트 PNG를 실제 사진 검증이라고 보고하지 않음.
- 검색·필터·뷰 기억·페이지·저장·수정·오류 후 입력 보존·원문·출처·첨부·사진 전체 보기 회귀 확인. 실제 외부 서비스·로그인은 실행한 범위만 기록.
- 기능/API/DB 변경 없이 디자인을 검증하고 전후 화면 및 남은 검증을 기록. 새로운 기능은 별도 승인·작업으로 분리.
