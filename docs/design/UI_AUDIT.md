## 현재 구조

Next.js 16.4.0 / React 19.3.0, `app/globals.css`의 전역 CSS와 CSS custom properties, `next/font/local`, 자체 React 컴포넌트다. Tailwind·UI 킷은 설치돼 있지 않다. 현재 구조 안에서 토큰과 클래스 규칙을 정리하면 충분하다.

`ProtectedLayout`이 앱을 `welcome-card protected-card` 안에 감싼다. 초기 안내용 스타일을 로그인·실제 보관함·상세·폼까지 공유하므로 전역 `h1`, `.auth-button`, `.welcome-card` 변경의 영향이 넓다. 실제 구현에서는 공통 토큰과 안내 전용 규칙의 적용 범위를 먼저 구분해야 한다.

## 폰트 적용 영향

현재 실제 기본값은 **나눔스퀘어라운드 Regular/Bold**다. 고운돋움 파일은 과거 비교용이다. 기존 WOFF2 합계는 파일 stat 기준 **479,300바이트**로 확인했으며 전송량·로딩 성능 측정값이 아니다.

Pretendard를 적용하면 제목·버튼 폭, 한글 개행, 긴 제목의 두 줄 경계, 입력 높이, 레시피 단위 정렬이 달라질 수 있다. 400/600을 실제 파일로 제공하고 세 번째 굵기나 새 의존성은 우선 추가하지 않는다. `font-synthesis: none`을 유지하며 기존 fallback·preload·워드마크의 관계를 확인한다.

[공식 Pretendard 저장소](https://github.com/orioncactus/pretendard)와 설치된 Next.js font 문서를 확인했다. 실제 도입할 파일의 버전·OFL·바이트·cold-load/CLS는 아직 검증하지 않았다. 과거 시안의 CDN 부분집합 전송량을 로컬 폰트의 예상 용량으로 사용하지 않는다. 사용 중인 구 폰트 파일/라이선스 삭제는 참조를 확인한 뒤 별도 판단한다.

### 대표 화면: 보관함 · 정갈한 레시피 아카이브

PC는 기존 최대 폭에서 상단에 차곡 워드마크·중립 로그아웃, 다음 줄에 ‘나의 보관함’과 노란 ‘새 항목 저장’을 둔다. 검색과 필터는 중립색으로 정렬하고 현재 ‘최근 저장순’ 문구·보기 전환을 유지한다. 콘텐츠는 카드형 3열/태블릿 2열, 사진 8:5와 제목 중심으로 구성한다. 목록형은 현재 작은 표지와 구분선 구조를 재사용한다. 날짜·태그는 13~14px 보조 정보로 낮춘다.

모바일 320px에서는 좌우 16px, 제목/등록 행동 → 검색 → 태그·즐겨찾기 → 보기 전환 → 콘텐츠 순서를 제안한다. 필터를 억지로 한 줄에 넣거나 중요한 기능을 숨기지 않는다. 사진 없는 항목은 캐릭터 큰 표지 대신 텍스트 중심의 낮은 중립 영역을 검토한다. 빈 보관함에서만 작은 노트 그림과 다음 행동을 안내해 차곡의 즐거움을 남긴다.

상세는 PC 재료/단계 두 열과 모바일 한 열, 폼은 원문/저장 결과의 연속된 두 구역을 추천한다. 새 화면 구현·새 시안 HTML 제작은 이번 단계에서 수행하지 않았다. 다음 구현 승인 전 같은 콘텐츠로 Pretendard·새 색상·반경·사진 유무를 확인할 대표 화면 시안을 제안한다.

## 기존 기능과 계획 구분

현재 목록은 페이지 이동 방식이며 정렬 선택 컨트롤은 없다. 좌측 플로팅 제목 목차·무한 스크롤(#32)은 계획을 보존한다. 현재 상세는 인분 문자열·재료/단계를 표시하지만 자동 분량 조절·버전/수정 이력·평가·전용 단계 탐색 UI는 없다. 현재 폼에는 초안 복원·저장 중·오류 처리가 있다. 성공 시 상세로 이동하며 전용 저장 완료 알림은 없다.

이 기능들을 디자인 작업 안에서 조용히 추가하지 않는다. 안내용 가짜 컨트롤도 만들지 않는다. 데이터/API/권한·저장 로직을 바꾸지 않고 스타일과 정보 위계부터 개선한다.

## 이번 단계 검증

새 팔레트의 상대 휘도와 대비를 계산하고 흑백 21:1 기준값으로 계산식을 자체 확인했다. 브랜드·의미 토큰의 결과를 시스템 표에 기록했다. 문서 링크·스킬 frontmatter·공백 오류와 변경 파일 범위를 확인한다.

제품 코드를 변경하지 않아 앱 테스트·빌드·DB·로그인 회귀를 이번 작업의 검증으로 실행하지 않는다. 전체 UI 대비, hover/pressed·opacity, 실기기·스크린리더·브라우저 확대·현재 화면 렌더링·폰트 로딩 성능은 실제 리디자인 단계에서 검증해야 한다.
